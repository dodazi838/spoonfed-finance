# 원문 근거 점검 (v1.6.0)

v1.6.1은 명확한 순차 로마숫자 대제목을 감지하면 원문 목차와 번호 붙임을 기준으로 물리적 챕터 범위를 확정합니다. 붙임 내부의 로마숫자 항목과 참고 박스는 상위 챕터 안에 유지합니다. 텍스트가 부분 추출되었거나 구조를 확정할 수 없으면 모델의 목차 추출을 사용합니다. 범위와 목차 보정은 추적 기록에 남깁니다.

업로드 완료 시 `pdf-parse`로 최대 200페이지, 300,000자의 텍스트를 추출합니다. PDF SHA-256을 브라우저 파일 해시와 대조하고 실제 페이지 수를 분석 분기와 추적에 사용합니다. 스캔·추출 실패·분량 제한은 부분/불가 상태로 표시하며 기존 PDF 분석은 유지합니다.

Gemini는 `sourceReview.facts`에 지표·시점·단위·통계 기준·대상·물리적 PDF 페이지·인용문을 반환합니다. 서버는 공백을 정규화한 연속 인용문이 해당 페이지에 있는지, 그 안에 수치가 있는지 대조합니다. 조/억 복합 금액도 대조합니다. `matched`는 인용문과 숫자의 존재만 확인한 상태입니다. 의미상 동일한 지표인지, 표 열 해석이 맞는지, 인과 설명이 타당한지를 독립적으로 입증하지 않습니다.

일치한 근거끼리 지표·시점·통계 기준·대상·단위가 모두 같으나 값이 다르면 충돌로 표시합니다. 어느 값이 맞는지 선택하지 않습니다. 모델이 다른 명칭·단위로 추출하거나 주요 근거를 놓치면 탐지하지 못할 수 있습니다. `coverage`와 `caveats`는 모델 자체 점검으로 화면에 명확히 구분합니다.

보고서 서고에는 점검 결과·인용문·시리즈 정보만 저장하고 전체 추출 텍스트는 분석 추적의 `sourceEvidence` 및 실제 프롬프트에 보존합니다. 기존 owner별 Firestore 규칙을 그대로 사용합니다. JSON 원본 응답, 대조 후 응답, 실제 표시 차트를 따로 남겨 원인을 비교할 수 있습니다.

차트 `series`는 `{ key, unit, basis }`, 각 데이터 행은 `{ name, periodType, period, [key]: number | null }`입니다. 단위·기준별로 그래프를 분리하며 시계열에 혼합된 연간·분기·월간·일간 자료도 분리합니다. 메타데이터 없는 기존 차트는 이름과 명시 단위로 제한적으로 분류하고 불명확하면 단위 확인 필요를 표시합니다. 이미 AI가 결측치를 0으로 반환한 이전 분석의 값은 추정 수정하지 않습니다.

검증: `npm run test:traces`, `npx tsc --noEmit`, `npm run build`. 실제 중국 보고서 회귀 자료는 `scripts/fixtures/china-report-quality.json`에 기록했습니다. 새 분석 시 실제 모델의 추출 품질도 확인해야 합니다.
