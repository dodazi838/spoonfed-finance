# 분석 추적 기능 (v1.5.0)

분석 결과의 **분석 기록**을 열면 분석 ID, 저장 상태, 요청별 복구 경고를 확인하고 JSON을 내려받을 수 있습니다. 보완할 점을 메모로 남길 수 있으며, 서고에서 분석 ID로 검색할 수 있습니다. 기존 분석에는 추적 기록이 소급 생성되지 않습니다.

## 기록에 포함되는 항목

- `input`: 파일명·크기·SHA-256, 페이지 수와 판정 방식. `fallback-15`는 페이지 수를 판정하지 못해 기본값을 썼다는 뜻입니다.
- `calls`: 전체 요약과 각 챕터 요청. 같은 `analysisId`로 연결하고 각 호출에는 별도의 `requestId`를 부여합니다.
- `versions`: 앱 버전, 프롬프트 버전, 배포 커밋. Vercel의 `VERCEL_GIT_COMMIT_SHA` 또는 수동 배포 시 `APP_BUILD_COMMIT`을 사용하며, 없으면 `local-unversioned`로 표시합니다.
- `prompt`: 실제 프롬프트와 SHA-256. 프롬프트 변경 시 `PROMPT_VERSION`도 올려 주세요.
- `model`: 요청 모델, 제공자가 응답에 포함한 경우 실제 모델 버전, temperature, 출력 토큰 한도.
- `rawResponse`, `finishReason`, `usage`: AI 원본 텍스트, 종료 사유, 토큰 사용량.
- `parse`: 직접 파싱/코드블록 제거/JSON 범위 추출/본문 부분 복구/실패와 경고.
- `parsedOutput`, `output`, `transformations`: 파싱 직후 값, 서버 보정 후 값, 보정 내역.
- `result`, `displayedMarkdown`, `displayVersion`: 완료 시점의 결과와 실제 화면 표시용 문안, 당시 앱 버전.
- 다운로드의 `viewedResult`, `viewedMarkdown`, `viewedAppVersion`: 현재 열어 본 화면의 결과와 문안. 나중에 서식을 수정해도 최초 표시와 비교할 수 있습니다.
- `clientEvents`, `feedback`: 업로드/통신 실패, 서버 추적 응답 누락, 사용자 보완 메모.

API 키·인증 토큰·Google 업로드 파일 URI·PDF 원본은 기록하지 않습니다. JSON에는 보고서의 분석 내용과 AI 응답이 포함됩니다. 원문 검증에는 동일한 PDF가 별도로 필요합니다. AI의 내부 사고 과정은 기록 대상이 아닙니다.

현재 구현은 서버가 반환한 기록을 브라우저에서 보관합니다. 서버가 응답하기 전에 탭을 닫거나 연결이 끊기면 해당 호출의 원본 AI 응답을 회수할 수 없습니다. 응답 없이 끝난 요청은 브라우저가 살아 있는 경우 통신 실패로 기록합니다. 탭 종료와 무관한 서버 보관이 필요하면 서버용 인증·저장소를 별도로 연결해야 합니다.

## 저장과 접근

브라우저 IndexedDB의 `spoonfed-analysis-traces/sessions`에 결과와 분리하여 보관합니다. 브라우저 저장이 실패하거나 응답하지 않으면 메모리에 유지하고 화면에 다운로드 안내를 표시합니다. 메모리 기록은 탭을 닫으면 사라집니다. 비로그인 기록은 해당 브라우저에서 확인할 수 있습니다.

Google 로그인 상태에서는 기존 Firebase 연결로 아래 경로에 클라우드 동기화도 시도합니다. 기록은 100,000 UTF-16 코드 단위 이하의 조각으로 나누고, manifest와 함께 원자적으로 저장합니다. UTF-8 변환에서 문자 손실이 없도록 서로게이트 쌍은 나누지 않습니다. 내려받을 때 전체 SHA-256과 모든 조각의 존재를 검사합니다.

`users/{userId}/reports/{analysisId}/analysisTrace/{manifest|chunk-N}`

**이 하위 컬렉션을 허용하는 Firestore 규칙이 필요합니다.** 기존 규칙이 보고서 문서만 허용한다면 클라우드 추적 저장은 실패하며 화면에 상태가 표시됩니다. 로컬 기록과 분석 결과는 계속 사용할 수 있습니다. 현재 규칙을 검토하고 아래 범위만 기존 규칙에 병합하세요. 프로젝트 전체를 공개하는 규칙으로 바꾸지 마세요.

```text
match /users/{userId}/reports/{reportId}/analysisTrace/{traceDoc} {
  allow read, write: if request.auth != null && request.auth.uid == userId;
}
```

계정이 있는 기록은 해당 사용자에게만 표시하며, 로그인 전 기록은 로그인할 때 계정에 연결합니다. 분석 ID는 공개 조회 토큰이 아닙니다. 분석 ID만 전달하면 다른 사람이 원본 기록에 접근할 수 없으므로 점검 시 JSON도 전달하세요. 브라우저 데이터 삭제, 저장소 정리, 클라우드 규칙/네트워크 문제는 보관에 영향을 줄 수 있습니다. 서고의 보고서를 삭제하면 연결된 추적 기록도 삭제합니다.

## 검증 및 배포

`npm run test:traces`는 실제 파서·API 라우트·저장 모듈을 실행하며 Gemini/Firestore는 테스트 대역으로 교체합니다. 실제 AI 호출 비용이나 운영 데이터 변경은 발생하지 않습니다. `npx tsc --noEmit`과 `npm run build`도 실행하세요.

배포 후에는 짧은 보고서와 긴 보고서 각각에 대해 분석 ID가 생성되는지, 다운로드에 원본 응답과 파싱 경고가 있는지, 새로고침 후 서고에서 다시 내려받을 수 있는지 확인하세요. 로그인 상태에서 클라우드 저장 완료 표시와 다른 기기에서의 읽기는 운영 Firestore 규칙을 적용한 뒤 확인해야 합니다.

프롬프트 개선에는 동일한 PDF와 동일한 챕터의 기록을 비교하세요. 수치·원문 근거·누락 여부는 별도로 검증해야 하며, 추적 기록이 있다는 사실만으로 분석이 정확하다는 의미는 아닙니다.
